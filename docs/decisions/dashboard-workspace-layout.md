# Owner dashboard in the workspace layout (2026-11-21)

The owner asked for the dashboard to use the backend template designed for the commercial application, with Approvals, Live log, Past runs and Start a run on a Settings page, and for all data generated by runs to populate it.

## Decisions made (for review)

1. **"The backend template" is the Blueprint workspace** of the customer site (`web/`, draft PR #16): the dark sidebar with Overview, Find work, Bids, Projects, Subs & vendors, Schedule, Money, Closeout, and Settings at its foot. Blueprint is the template that PR marks as chosen; Hi-Vis is not used here.
2. **Same server, rebuilt page.** The dashboard stays the small `node:http` server with its logins, HTTPS, CSRF and CSP. The page is rebuilt in the workspace layout as plain HTML and JS rather than by running the Next.js site, because the site's workspace component has its sample data built in and is generated from the design system (it must not be edited in this repo). Moving the dashboard into Next.js is a later step, once the design system's workspace takes real data.
3. **Every workspace screen is filled from runs** via `GET /api/workspace` (live runs plus the latest 20 saved ones):
   - Overview: waiting approvals, jobs in progress, bids awaiting award, awarded jobs, profit, and a jobs table.
   - Find work: every project the President looked at, pursued or passed.
   - Bids: quotes in per trade, estimate, bid and status.
   - Projects: contract, change orders, cost, problems solved, days late.
   - Subs & vendors: every subcontractor that quoted, with picked quotes and value.
   - Schedule: each job's schedule as bars against the contract length.
   - Money: contract value, invoiced, received, owed, paid to subs and profit, overall and by job.
   - Closeout: jobs being billed, paid and closed.
   - A job page (click any job): lifecycle stages, all facts, quotes, schedule, problems, the hired agent team and the owner's answered decisions.
4. **More run data in the projection:** each job now also carries the hired team (role, manager, budget, who hired it), answered decisions, the seed and the injected problems.
5. **Approvals under Settings, but not hidden.** As asked, Approvals is a Settings tab. Because agents stop until the owner answers, the Settings link and the Approvals tab carry a count, and Overview lists what needs you with a Review button that opens the tab.
6. **Screens have URLs** (`#bids`, `#settings/live`, `#job/<run id>`), so the back button and bookmarks work.
7. **Figures labelled "From your runs"** so the dashboard is never mistaken for the site's sample data.
8. **Browser test in CI.** `test/dashboardBrowser.test.ts` runs a scripted closeout run through the server and checks every screen and Settings tab in Chromium. CI now installs Chromium for the main job. Locally it is skipped unless `PW_CHROMIUM_PATH` points at a Chromium (or Playwright's own is installed).

## Not done

- The workspace's Find work does not list projects no run has looked at yet; the stub job list is still only under Start a run.
- No dark theme (Blueprint has none yet).
- Model and tool calls (spend per agent) are still only in Past runs, not on the workspace screens.
